# GLOWW — Botanical Skincare Storefront

A premium, fully responsive skincare e-commerce website for **GLOWW**, an original botanical skincare brand. It's built with **plain HTML, CSS and vanilla JavaScript**: no framework, no build step, no npm. It has working **Stripe checkout**, **Mailchimp newsletter sign-up** and a **contact form that delivers by email**, all powered by small serverless functions on Netlify.

**Live site:** https://delightful-piroshki-6bb719.netlify.app/

> GLOWW is an original brand created for this project. All product names, copy and product imagery are original. The product packshots are illustrated GLOWW packaging generated by `tools/generate-packshots.py`.

---

## Highlights

- **Editorial, luxury design system.** Warm ivory and botanical-green palette, self-hosted Cormorant Garamond and Jost typography, and subtle motion that respects `prefers-reduced-motion`.
- **Real shopping experience.**
  - A product catalog with live search, category, skin-need and price filters, sorting, and quick view.
  - Product detail pages and related products.
  - A persistent bag and wishlist (`localStorage`).
- **Secure payments with Stripe Checkout.** The browser sends only product ids and quantities. The server rebuilds every price from the catalog, so totals supplied by the browser are never trusted.
- **Newsletter** via Mailchimp, with double opt-in.
- **Contact form** emailed via Resend, with server-side validation and the visitor as Reply-To.
- **Accessibility.** Semantic HTML, a keyboard-accessible mobile menu and dialogs (focus trapping, Escape to close), visible focus states and labelled forms.
- **SEO and performance.**
  - Unique titles, meta descriptions and Open Graph tags on every page, plus `sitemap.xml` and `robots.txt`.
  - Responsive WebP images with lazy loading and explicit dimensions.
- **No secrets in the frontend.** API keys live only in Netlify environment variables.

## Getting started

**1. Clone the repository**

```bash
git clone https://github.com/FaizahYusuf/gloww-skincare.git
cd gloww-skincare
```

**2. Choose how to run it**

- **Quick preview: static only.** Browsing, search, the bag and the wishlist all work. Checkout, the newsletter and the contact form need the serverless functions. Without them, the site explains that these features are available on the live site.

  ```bash
  python -m http.server 8000
  # visit http://localhost:8000
  ```

- **Full local stack: with functions.** This uses the [Netlify CLI](https://docs.netlify.com/cli/get-started/), a developer tool that isn't part of the site.

  ```bash
  npm install -g netlify-cli      # one-time
  cp .env.example .env            # then fill in your TEST keys — .env is git-ignored
  netlify dev                     # http://localhost:8888, including /api/* functions
  ```

### Environment variables

All variables are listed, without values, in [`.env.example`](.env.example). In production, set them in **Netlify → Site configuration → Environment variables**. Never commit them.

| Variable | Required | Purpose |
|---|---|---|
| `STRIPE_SECRET_KEY` | For checkout | Stripe secret key (`sk_test_…` for testing) |
| `STRIPE_SHIPPING_COUNTRIES` | Optional | Comma-separated ISO codes (default `US`) |
| `STRIPE_AUTOMATIC_TAX` | Optional | `true` once Stripe Tax is configured |
| `MAILCHIMP_API_KEY` | For newsletter | Mailchimp API key (ends in `-usXX`) |
| `MAILCHIMP_AUDIENCE_ID` | For newsletter | Target audience ID |
| `MAILCHIMP_SERVER_PREFIX` | Optional | Data-center prefix (read from the key if omitted) |
| `MAILCHIMP_DOUBLE_OPT_IN` | Optional | `false` to skip the confirmation email |
| `RESEND_API_KEY` | For contact form | Resend API key with sending access |
| `CONTACT_TO_EMAIL` | For contact form | Inbox that receives messages |
| `CONTACT_FROM_EMAIL` | Optional | Verified sender, e.g. `GLOWW <hello@your-domain.com>` |

## Architecture

```
Browser (static HTML/CSS/JS)
  │  bag & wishlist in localStorage
  │
  ├── POST /api/create-checkout-session ──► Stripe Checkout (hosted payment page)
  ├── GET  /api/checkout-status ──────────► Stripe (order summary for confirmation page)
  ├── POST /api/newsletter-subscribe ─────► Mailchimp
  └── POST /api/contact-submit ───────────► Resend (email)
```

### How checkout works

1. The visitor clicks **Secure checkout** in the bag. The browser sends **only product ids and quantities** to `/api/create-checkout-session`.
2. The function validates the bag. Unknown products, invalid quantities and duplicates are rejected. It then rebuilds every price and the shipping charge from `js/products.js`, the same catalog the site displays.
3. Stripe hosts the payment page, so card details never touch this site.
4. Stripe redirects to `checkout-success.html?session_id=…`. That page loads the order from Stripe and clears the bag only once Stripe reports the payment as **paid**.
5. If the visitor cancels, they return to the shop with their bag intact.

## Common edits

- **Add or change a product.** Edit `js/products.js`. The shop, search, homepage rows, related products, bag and Stripe checkout all update automatically. Then add the product URL to `sitemap.xml`.
- **Change prices or shipping rules.** Edit `GLOWW.config` and the products in `js/products.js`. The checkout function imports the same file, so the amount charged always matches the site.
- **Change colours or fonts.** Edit the design tokens at the top of `css/base.css`. `navbar.html` shows the full design system.
- **Product images.** Edit the product's entry in `tools/generate-packshots.py`, then run `python tools/generate-packshots.py`. This needs `pip install playwright Pillow` and Microsoft Edge or Chrome.
- **Editorial photographs.**
  1. Add the original to `Images/`.
  2. Run `pip install Pillow` once.
  3. Run `python tools/optimize-images.py`.
  4. Reference the new file from `Images/web/`.

## Deployment (Netlify)

1. In Netlify, choose **Add new site → Import an existing project** and select this GitHub repository. There's no build command; `netlify.toml` configures everything.
2. Add the environment variables listed above in **Site configuration → Environment variables**. Their scope must include **Functions**.
3. Deploy. To test checkout end to end, use Stripe's test card `4242 4242 4242 4242` with any future expiry date and any CVC.
4. To take real payments, replace `STRIPE_SECRET_KEY` with your `sk_live_…` key and redeploy.

### Troubleshooting

**Health check.** Each function answers a `GET` with a status check that never reveals key values:

```bash
curl -i https://delightful-piroshki-6bb719.netlify.app/api/newsletter-subscribe
```

| Response | Meaning | Fix |
|---|---|---|
| `200` with `"configured": true` | Healthy | — |
| `200` with `"configured": false` | Variables are missing or not scoped to Functions | Check the names and scope, then redeploy |
| `401` HTML "Login Redirect" | Netlify visitor access protection is on | Turn off site protection for production |
| `404` | The function isn't deployed | Redeploy from the project root |

Each submission writes a status code to the Netlify Function log, for example `SUBSCRIBED`, `NOT_CONFIGURED` or `MAILCHIMP_AUTH_FAILED`. Visitors only ever see friendly messages.

## Security notes

- Secret keys are read only from environment variables inside Netlify Functions. They never appear in frontend code or in git.
- `.env`, `.env.*` (except `.env.example`) and the local `.netlify/` folder are git-ignored.
- Prices and shipping are recalculated on the server. Browser-supplied totals are ignored.
- Payment details are entered on Stripe's hosted page, never on this site.
